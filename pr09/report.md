# ПР №9. Лицензирование и Open Source Compliance

## 1. Выбор лицензии

### Выбранная лицензия

**Лицензия:** MIT License

**Тип лицензии:** Разрешительная (Permissive License)

### Основные возможности лицензии MIT

Лицензия MIT предоставляет пользователям следующие права:

* использование программного обеспечения;
* копирование исходного кода;
* изменение и модификация кода;
* публикация и распространение;
* сублицензирование;
* коммерческое использование и продажа.

### Обязанности пользователей

При использовании программного обеспечения необходимо:

* сохранить текст лицензии;
* сохранить уведомление об авторских правах (Copyright Notice).

### Возможность коммерческого использования

Лицензия MIT допускает продажу программного обеспечения и производных работ при условии сохранения исходного уведомления об авторских правах.

### Анализ результата

| Параметр          | Значение    |
| ----------------- | ----------- |
| Лицензия          | MIT         |
| Совпадение        | 100%        |
| Метод определения | Exact Match |
| Проверяемый файл  | LICENSE     |

### Что означает процент совпадения

Параметр **Confidence** показывает степень совпадения содержимого файла LICENSE с эталонным текстом лицензии.

Значение **100%** означает полное совпадение с официальным текстом лицензии MIT.

### Как GitHub определяет лицензию проекта

GitHub автоматически анализирует файлы:

* LICENSE
* COPYING
* LICENSE.md
* LICENSE.txt

Для определения лицензии используется библиотека **Licensee**, которая сравнивает содержимое файла с набором известных лицензий.

## 5. Проверка лицензий в CI/CD

### Конфигурация GitHub Actions

```yaml id="7r4v4r"
name: License Check

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  licensee:
    name: Check repository license
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Install licensee
        run: gem install licensee

      - name: Detect license
        run: |
          licensee detect .
          echo "License check passed"

  reuse:
    name: REUSE compliance check
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: REUSE compliance check
        uses: fsfe/reuse-action@v3
```

### Результаты проверки

| Проверка | Статус         |
| -------- | -------------- |
| Licensee | Успешно        |
| REUSE    | Предупреждение |

### Причина предупреждения REUSE

Не все файлы проекта содержат SPDX-заголовки, поэтому проект не полностью соответствует требованиям спецификации REUSE.

### Добавление GPL-зависимости

При добавлении зависимости под лицензией GPL:

* лицензия будет отображена в отчёте;
* система CI сможет обнаружить её наличие;
* предупреждение появится в отчётах проверки.

Остановка сборки возможна только при дополнительной настройке политики контроля лицензий.

## 6. Анализ совместимости лицензий

### Сценарий 1. MIT + GPL в коммерческом проекте

Использование GPL-компонента в распространяемом коммерческом продукте требует раскрытия исходного кода производного программного обеспечения.

**Вывод:** для закрытого коммерческого продукта данный вариант нежелателен.

### Сценарий 2. Apache-2.0 + MIT

Обе лицензии являются разрешительными и совместимы друг с другом.

**Вывод:** использование допустимо.

### Сценарий 3. MIT без указания авторства

Лицензия MIT требует сохранения уведомления об авторских правах.

**Вывод:** отсутствие указания автора является нарушением условий лицензии.

### Сценарий 4. AGPL в SaaS-сервисе

AGPL требует раскрытия исходного кода даже при предоставлении доступа через сеть.

**Вывод:** использование AGPL нежелательно для закрытых SaaS-проектов.

### Сценарий 5. Отсутствие LICENSE

При отсутствии лицензии программный код автоматически защищён авторским правом.

**Вывод:** использование такого кода без разрешения автора недопустимо.
